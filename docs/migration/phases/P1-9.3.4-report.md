## 已完成的兼容实现

`emtaint/solver/port.py` 的有限纯 BV DTO 不含 Claripy 原生类型，不充当 P3 CIR。约束批次用平衡树做联合类型检查，避免 528 条浅约束被左深验证树误判为超深；保留节点、深度、宽度、查询超时和枚举限额。`SolverResult` 禁止转 bool，调用者必须检查 SAT / UNSAT / UNKNOWN / TIMEOUT / UNSUPPORTED / ERROR / CRASH。

`solver/backends/ast_tools.py` 保留旧 occurrence 前序和 leaf LIFO 去重次序，区分 expanded 与 unique，使用结构 SHA 而不是跨版本裸 hash。旧 BVS 七参数与新 BVS 两参数仅在普通无界 BV 子集归一化。新版本使用模块级 `claripy.replace`，旧版本保留 AST 方法；不匹配位宽或 sort 显式拒绝。非空 annotation、VSA bounds、未知操作不会被抹去。

`claripy_adapter.py` 固定目标 `.venv`、9.3.4 包元数据与 Claripy 模块路径；无全局或旧环境回退。仅经过版本和实测确认的目标工厂将 `satisfiable() == False` 解释为 UNSAT：本地 9.3.4 `backend_z3.py:262` 的 `z3_solver_sat` 对 Z3 UNKNOWN 明确抛异常。任意注入模块默认仍将 False 解释为 UNKNOWN；不凭 `check_satisfiability` 名称猜测可靠性。

异常链中的明确 timeout 返回 TIMEOUT；非超时 unknown、resource limit 返回 UNKNOWN；其他后端错误返回 ERROR。`SubprocessSolverPort` 使用固定目标解释器，每个查询有独立请求、缓存、stdout/stderr/checkpoint/结果和退出码；父进程截止终止 venv launcher 与 worker 树。原生异常退出为 CRASH，无法产生 UNSAT 或“零发现”。直接 Z3 探针仅用于诊断，没有作为运行回退。
