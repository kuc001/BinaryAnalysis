## Contract translation

- **Alias:** VEX register/stack/global heuristic address → CIR pointer definition → Memory Object + Access Path + candidate MemoryLocation at a MemoryVersion → budgeted Alias Query → Alias Evidence. `May/Unknown` is retained when exact identity, width, guard or offset is unproved. `NoAlias` needs complete separation evidence. No legacy `alias_id` becomes a public identity.
- **SSE:** `TraceExpr` AST and mutable queue → CIR Definition/Value IDs plus hash-consed `SymbolicExprId` DAG. Forward/backward queries reference one dependency graph and versioned memory reads. Copy/kill/merge must specify path guards, precise write coverage and completeness. Many-to-many source/CIR provenance is separate from expression equality.
- **Indirect call:** `Iptr` → Callsite target expression; `Fptr/Vptr` Store → Memory Definition; candidate substitution → Alias Query and candidate target evidence; code validation → Confirmed or Ambiguous/Unresolved Target; publish Refined CG revision only after validation. Old `maybe_function` and table enumeration supply candidates, never certainty.
- **Taint:** legacy source IDs and `Tdata` → versioned Source/Sink identities, Demand Context, CIR Value and MemoryVersion. Procedure/callee effects become Function Summary; each propagation edge carries evidence, guard, uncertainty, context and budget status. A candidate path and a validated vulnerability remain distinct result types.

## New architecture inspection and gap list

`core/contracts.py` and `core/identity.py` currently give typed IDs, values, assessments and origins, while `ir/canonical/model.py`/`wire.py` serialize CIR v1 effects. The accepted architecture direction requires later CIR v2/HIR freeze; this audit does not edit either. `frontends/*` acquire VEX/IDA-derived inputs; no structured CTree production path was established. `memory/state.py`, `engine.py`, `query_port.py` provide version, interval and alias primitives; `analysis/aliasing/query.py` already classifies a demand query, so “alias absent” would be false. `analysis/sse/dag.py` and `analysis/dataflow/accurate.py` implement a CIR subset, not the complete B/F legacy engine (the latter says this explicitly in its module docstring). `orchestration/icall_program.py` and `taint_program.py` expose existing program paths, but their persistence, provenance, context and old-case coverage must be verified separately. `analysis/taint/demand.py` already has bounded partial summaries; no evidence in this static audit proves cross-frontend equivalence. `solver/*`, `analysis/framework/summaries.py`, `analysis/bugfinder/*` are supporting modules, not evidence of a fully migrated algorithm.
