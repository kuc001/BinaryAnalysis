# ACR-F1-INTEROP-001 · Shared CIR semantics for VEX interoperability

**Status: Proposed. Owner decision and date: pending.** Linked task `F1-VEX-CIR-V2-INTEROPERABILITY` and ADR-001/004/008/010/011/012. P1 readiness blocker. Presenting an incomplete register or memory mapping as precise would be a P0 semantic error.

The pinned F0 `_start` control input demonstrates 35 register effects, three SUB operations, typed byte accesses and a computed transfer. The new same-function F0 acquisition also exhibits 179 register effects, 23 memory effects, four calls and two conditional effects. F1's existing Common CIR-Wire-v2 profile cannot validate all of their architectural inputs and state transitions. See the [v1 inventory and mapping matrix](F1_VEX_CIR_V2_INTEROPERABILITY_AUDIT.md) and [same-function readiness report](F1_TRANSLATION_VALIDATION.md).

| Decision | A · Versioned Shared Semantic Profile (recommended) | B · Mandatory Semantic Appendix bound to CIR Body Digest |
| --- | --- | --- |
| Schema versioning | Use a new, explicitly dispatched shared semantic profile and artifact format. Freeze exact identifiers and fields before implementation. Keep the existing CIR-Wire-v2 reader and bytes | Keep the current body format. Specify a separate appendix version and capability identifier in the new Manifest. Bind appendix to full CIR body, CFG, function and policy digests |
| Definition and Use identity | Explicit effect slot, definition occurrence and operand role IDs scoped to binary/function/profile/revision. Register and memory state are first-class definitions and uses | Bind the same identities in the appendix, with a total checked mapping from body slots to semantic facts. Reject duplicate, dangling or incompatible binding |
| Register state and scalar operations | Define architectural register slices, writes that preserve or zero untouched bits, guarded state and predecessor merges. Define bitvector/pointer widths, signed interpretation, address spaces, modular arithmetic, comparisons, extraction, extension and concatenation | Carry the same normalized typed facts and state links in appendix entries. They are part of the common view. Original VEX text or opcodes alone are insufficient |
| Memory, guard and endian | Define typed pointer/space, byte width/range, endian, alignment, volatility and guard. Carry guarded memory versions and explicit possible modification | Store the same access/state descriptors in the appendix. Validate descriptor spans and guard uses against effect slots to reject drift |
| Call and clobber | Shared callsite identity, direct/indirect/external/unknown targets, ordered uses/results, ABI evidence, guarded continuation, may-read/write and register clobber | Bind those call records and state transfers to body call slots. C1 consumes the validated combined view |
| CFG and Origin | Preserve source block mode, bounds, edges and uncertainty. Represent unresolved computed exits and synthetic joins explicitly. Retain many-to-many source origins and reasons | Keep body graph and appendix evidence separately bound. Project through the same common graph API after cross-validation. Unknown successors remain visible |
| Provenance and Manifest | Version the converted producer, body and graph. Bind input artifact, address, coverage, and exact/partial/unsupported mapping records to immutable output | Also pin the appendix digest/schema and require all parts to validate together. Two separately valid files are insufficient if the binding fails |
| Readers and historical artifacts | Dispatch new readers by profile. F0 v1 and F1 v2 artifacts retain their original codecs, identities, digests and interpretations. Any cross-version conversion publishes a separate generation | Existing F0/F1 reads remain valid for their existing capabilities. A consumer requesting extended semantics must refuse to analyze if the appendix is missing, stale, incompatible, mismatched or unverified |
| C1 gate | Accept a shared input only if the selected real Store→Load dependency preserves register, address, guard, width, endian, reaching memory and Origin evidence | Enforce the same gate through the checked combined view. Generic v2-only clients cannot silently fall back to the partial body for C1 |

Both options are **frontend-neutral**. CTree, VEX and later frontends must bind common typed operations, state and evidence. Producer artifacts can retain frontend-specific metadata under explicit provenance. Neither option defines a competing frontend-specific analysis truth.

**Recommendation.** Select A to keep the state transitions required by C1 in one versioned semantic body. B offers stronger body-format compatibility and more cross-artifact validation and misuse risk. Existing `unknown` effects can preserve conservative footprints, but cannot certify a dependency when guard, endian, register identity or reaching memory is unavailable.

**Verification and containment.** Require deterministic conversion under the selected version for the original `_start` and exact `0x632F8` v1 pins. Account for every effect and operand, preserve typed byte and control evidence or mark reasoned unknowns, and require detached reload. Recheck old v1/v2 readers against original pinned generations. Require the authentic IDA Machine Validation input and the five translation levels in the separate report. On failure, leave original bytes and readers intact and withhold the new capability and any C1 claims. Approval of this ACR does not approve C1.

**Decisions requested.** Choose A or B, approve schema/manifest dispatch and compatibility, agree on the required observable state transitions and unsupported behavior, approve the IDA validation witness and later adapter scope. Exact version names and acceptance ownership remain pending.
