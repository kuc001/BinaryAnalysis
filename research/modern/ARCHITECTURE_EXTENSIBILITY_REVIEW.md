## 3. Alias, access and strong update: two candidates

**Relations are separate:** pointer equality is a proof that two pointer *values* denote the same concrete address in a context; pointer aliasing asks whether their possible addresses can coincide; access overlap asks whether the *byte intervals read/written* intersect (equal base with widths 1 and 4 overlaps but is not equal coverage); byte coverage asks which read/old-definition bytes a write replaces. Same abstract MemoryObjectId only groups candidates. Different IDs can still alias unless disjointness is proved. Equal numeric address representations in different address spaces need a validated conversion. Guard and MemoryVersion scope every claim.

| Choice | Shape | Compatibility / cost | Risk |
|---|---|---|---|
| **A (recommended)** | Retain four-way `AliasKind` for *address relation*; add separately assessed `AccessOverlap` (`DISJOINT`, `EXACT`, `PARTIAL`, `CONTAINS`, `WITHIN`, `UNKNOWN`) and `ByteCoverage` (covered half-open byte ranges, uncovered ranges, endian, completeness/evidence) for each feasible location pair. | Keeps callers of `AliasKind` semantically narrow; bounded analysis-level result can be trialed on CIR v1. Needs explicit composition rules and versioned result schema before persistence. | Must ensure a no-overlap byte proof cannot be misreported as `NO_ALIAS` pointer relation. |
| B | Extend `AliasResult` with independent address relation, access relation, coverage, evidence/status axes. | One object is convenient but changes current `memory/state.py` public/wire assumptions and callers; wider schema freeze and compatibility migration. | Old callers may still interpret the legacy `MUST_ALIAS`/`NO_ALIAS` field alone. |

**Recommended C1 rule:** use A as the proposed *analysis result* boundary, with explicit fields and no CIR wire edit in R1-C. For every feasible Store/Load pair, first resolve pointer alternatives and address relation, then compare byte intervals and widths. An address `NO_ALIAS` requires complete separation of all feasible address alternatives. An access `DISJOINT` can remove that specific byte dependency even when pointers have the same base but nonoverlapping offsets; it does **not** prove pointers cannot alias. `MAY_ALIAS` means a feasible overlap remains, not equality. `UNKNOWN` or PARTIAL/TIMEOUT/UNSUPPORTED keeps a possible dependency. Strong update requires a unique live concrete target, complete exact coverage of the bytes being killed, effective guard true on the path, ordered write, supported effects and complete proofs for every alternative. Partial overlap can kill only proved covered bytes; untouched bytes preserve old definitions. Havoc creates an explicit unknown producer.

## 4. Three identities and C1 persistence gate

- **Expression identity:** DAG node key for symbolic operation/operands/type/origin/location/state. Current `SymbolicExprDAG` can intern nodes locally. Repeated syntax does not imply equal runtime fact.
- **Analysis fact identity:** `(query scope, program point, definition/use, memory version, guard abstraction, call context, policy, source set, activation/status)`. A merge is valid only if observations under forward and backward queries are preserved; if sources differ, preserve a representative-to-members witness and replay them before any result/evidence endpoint. C1 does not implement merge.
- **Value-flow dependency identity:** `(producer DefinitionId, consumer UseId, dependency kind, relevant byte range, guard, memory version, derivation/evidence, graph revision)`. An edge is a semantic relationship, not a DAG node. Candidate and proven edges have distinct status; unexpanded candidates are `PENDING`/incomplete.

For C1 v1-derived **private** IDs, define a canonical recipe under an approved version: `sha256(domain tag || CIR body hash || acquisition/producer fingerprint || binary ID || function ID || CFG revision || block ID || effect ordinal || output/use role || role ordinal)`. Validate the CIR body hash and producer before indexing; sort only unordered input maps canonically; retain ordered effect slot exactly. The result envelope records the recipe version and all ingredients, maps each ID back to a current effect/role, and rejects reload when any ingredient or mapping differs. A private ID may appear in an **analysis-owned, versioned result schema** only if that schema binds the exact recipe and artifact and does not claim it is a durable CIR v2 ID. Bare in-memory IDs may not cross process or artifact boundaries. C1a may deliver inspectable in-process semantics; C1b supplies deterministic persistence, reload, invalidation and read-only inspection. **C1 is complete only after both.** If current v1 reader cannot provide a stable artifact/revision tuple or role mapping, stop at C1a and seek owner approval for the minimal formal identity contract; do not advertise C1 as finished. A true cross-artifact stable DefinitionId requires a separate CIR v2 freeze with compatibility and provenance mapping.

## 5. Real CIR input preflight

`frontends/saved_cir.py:18-91` is the **preferred existing reader**: it reconstructs a module from saved `cir/function-*.json`, `architecture.json`, `producer.json`, `assessment.json`, `origins.json`, `frontend-report.json` and returns body hashes. The report's `cfgs` rows are emitted by `frontends/vex_lowering.py:106-117` with node tokens, edge tuples and status. `load_saved_cir` does **not** reconstruct a `ControlFlowGraph`; C1 needs a bounded report-to-CFG reader that validates every token/edge against the module blocks, entry and origin mapping, rejects inconsistent/missing rows, and fingerprints the validated CFG. This is an input adapter, not a script compatibility layer. The saved reader checks aggregate byte budget and typed wire/model constraints, but does not itself verify the binary image hash or provenance JSON cryptographically against an external manifest. C1 preflight must select a saved acquisition with Store/Load, validate hashes against a trusted acquisition receipt and CFG/origin integrity, and bind a declared CFG revision. A repository and `firmware-binaries` file search found no *new-format* saved CIR acquisition; historical `references/legacy-emtaint/data` JSON is not a C1 fixture. The reader's existence alone does not prove a usable on-disk acquisition is currently present.

Alternative: `frontends/function_store.py` reads per-function CIR bodies with `cir_sha256` and reconstructs CFG from frontend metadata, but `:16` requires `acquisition-report.json` with `passed` and `violations`, a guard-era receipt shape. Only use it if an actual compatible saved acquisition is identified and verified. A bounded reader adaptation may be needed; old scripts are not restored. `frontends/angr_vex/frontend.py` and `frontends/ida_vex/frontend.py` remain native frontend paths; `vex_input.py` requires a target `.venv` and pinned native packages. These are fallback *acquisition* options under a separate approved environment/input gate, not evidence that R1-C ran a binary. A hand-constructed CIR unit fixture validates semantic rules but cannot establish real binary end-to-end capability. C1 acceptance therefore has two witnesses: an explicit saved/lifted artifact with hashes, CFG, origin and Store/Load metadata, plus persist/reload of its dependency result; otherwise report C1 input integration as open.

## 6. Query, precision and dependency ownership

`QueryIdentity` is a stable request key, not the whole context. `AnalysisContext` binds binary/artifact, function/CFG/CG revision, MemoryVersion, call string/object context and path guard. `PrecisionPolicy` selects screening, sparse traversal, demand alias, context refinement and optional SMT, including fallbacks. `QueryBudget` only caps node visits, alternatives, solver calls/time, memory and expression growth; increasing it may complete a query but does not change policy semantics. `SolverRefinement` is an evidence-producing step with assumptions, timeout and counterexample/proof scope. `Completeness` and `AliasEvidence` are independent result axes. Fast screening may prove address `NO_ALIAS` only from complete object/address separation, or prove access `DISJOINT` from complete byte-range separation; sparse traversal may return a pending frontier; on-demand alias refinement may narrow candidates; context refinement requires call/heap identity; SMT refinement requires faithful bit-width, address-space, guard and memory axioms. Timeout never becomes NoAlias.

Layer ownership: CIR/Program/Memory/Provenance own immutable semantics and graph revisions; a **dependency index** (when C1 consumes it) owns scalar/memory producer-use edges and pending candidates; forward/backward worklists and future IFDS/IDE/lazy/replay are strategy consumers; result/evidence/cache persist scoped answers; Inspector only reads them. SSE DAG owns expression terms and substitutions, not MemoryObject identity, AliasQuery truth, CG or summary revisions. Dependence is one-way `semantic → dependency → strategy → result`; strategy may query semantic ports but cannot mutate acquisition facts. Debug presentation never performs a new query.

## 7. Incremental dependency and invalidation policy

| Dependency (identity and revision) | Invalidation / cache reuse precondition | Unknown footprint |
|---|---|---|
| CIR artifact hash + lowering revision → Definition/Use index revision | Reindex changed function/roles; reuse only with exact body and recipe/version match. | Reindex whole affected function. |
| DefinitionId → UseId / StoreId → LoadId at CFG and MemoryVersion revision | Recompute reachable edges after changed effect/order/guard/CFG or memory semantics. | Keep candidate edge; invalidate all potentially touched loads. |
| AliasEvidenceId + query context/version → ValueFlowEdgeId | Any new candidate, policy, budget, solver or memory version invalidates prior scoped negative; stronger proof may add/remove edges. | Unknown footprint is wildcard, never absent. |
| CG revision → procedure summary revision → caller query revision | Added/removed iCall target or changed callee summary invalidates callers transitively to fixed point. | Unknown callee invalidates conservative caller footprint. |
| Taint policy revision → taint result | Re-run analysis from unchanged semantic facts if only source/sink/model policy changes. | Unknown model broadens affected sinks/calls. |
| Analysis result ID → evidence artifact ID / Inspector view | Rebuild or mark stale after dependency change; display matching stored revision only. | Report evidence unavailable/stale, do not silently query. |

Changes to CIR bytes, frontend lowering, origin/provenance mapping, loader/relocation or binary image can require **Acquisition rerun** (or a new immutable acquisition artifact) plus analysis invalidation. A new alias relation, new iCall target/CG edge, changed summary, solver policy/budget, or taint policy with unchanged source artifact requires **Analysis rerun only**. A provenance mapping change creates a new evidence/source artifact revision even when semantic CIR bytes are identical; semantic results may be reusable only if their dependency and trust assumptions do not depend on that mapping, while explanations must be rebuilt. Acquisition Cache keys source/export inputs and producer; Analysis Cache keys CIR/CFG/CG/memory/policy/solver/result contract. They cannot share one semantic validity rule. A SILVA-style local recomputation requires all edge derivations, including multiple sources; absence of a known derivation is not proof of absence.

## 8. C1 scope, experiments and verification design

**Freeze before C1 code:** four-way address AliasKind and independent access/coverage conclusion; unknown/partial/timeout rules; query-point MemoryVersion and guards; Def/Use/edge identity recipe and persistence envelope; result/evidence status and invalidation; real CIR input and module ownership. These are narrow C1 contracts, not whole CIR v2 approval. The P0 wrapper path is first acceptance. C1a establishes Store/Load byte semantics, uncertainty, shared forward/backward dependency answers and inspectable evidence; C1b establishes deterministic persisted result, hash/revision validation, reload, invalidation and read-only Inspector. The backlog's ten semantic cases remain required.

**Defer:** complete Hermes LSEG, CFL/IDE, Merge-Replay, selective object sensitivity, SILVA incremental PTA/Mod-Ref, full pointer analysis, interprocedural taint and iCall recovery. C2 may compare (a) proven pure-copy pruning against unpruned Def/Use, (b) lazy bounded memory-edge expansion against a complete bounded graph, and (c) common dependency consumption by iCall/taint policies. C3 may prototype CFL transformers on field-like offsets, merge/replay with proof witnesses, selective context on bounded CG and incremental invalidation versus full recompute. Each is a separate owner task.

**Future verification, not run here:** semantic matrix Must/May/No/Unknown × access exact/partial/disjoint × guarded/strong/weak/join/havoc/budget; bidirectional answer and evidence consistency; pruning/lazy/merge/cache-hit versus unoptimized/full recompute equality; CG edge insertion/deletion, summary and memory effect/policy changes; stale-result rejection. Record query time, visited CFG/value-flow nodes, alias queries, SSE nodes, memory, reanalyzed functions and expanded edges **alongside** precision/unknown rates. TaintCC-style transformations are admissible only with a documented preservation proof for binary/CIR guard, width, address, memory and source/sink behavior.
